# TubeMail OSS Launch Plan — 2026-04-25

Status: **draft for same-day launch**. Use the checklist at the bottom; the
sections above are the reasoning so the checklist isn't blind.

---

## 1. The state we're launching from

- Repo: `disciplin-run-org/tubemail` — currently **private**, 0 stars, no
  description, no homepage URL, no topics, no GitHub release, no
  SECURITY.md / CONTRIBUTING.md / CHANGELOG.md.
- Code: v0.2.0, MIT, 143 tests green, CI on every push, Docker image
  builds, frontend bundle vendored.
- Docs: README.md (269 lines, dense) + TUTORIAL.md (454 lines, good).
- Distribution: PyPI **not yet published** (`tubemail` and `tubemail-hub`
  return 404). Docker image not on a public registry.
- Visual assets: **none** — no screenshots, no GIFs, just the favicon.
- Footprint: full FastAPI + React product with web UI, MCP tool surface,
  pty bridge, recording, permission inbox. Substantial.

The product is shippable. The launch surface is not.

## 2. Competitive landscape (April 2026)

The "manage parallel Claude Code sessions" space has filled up fast.
Here's how each competitor positions itself, in their own words.

### Direct competitors

| Project | Tagline | Type | Note |
|---|---|---|---|
| **Claude Squad** (`smtg-ai/claude-squad`) | "Manage multiple AI terminal agents like Claude Code, Codex, OpenCode, and Amp." | OSS terminal app | Most-starred. Multi-agent, git worktrees. |
| **Crystal → Nimbalyst** (`stravu/crystal`) | "Run multiple Codex and Claude Code AI sessions in parallel git worktrees." | OSS desktop app | Rebranded Feb 2026 to "AI-native workspace". |
| **Conductor** (`conductor.build`) | "Run a team of coding agents on your Mac." | Paid Mac app | Cleanest pitch. Closed source. |
| **Container Use** (`dagger/container-use`) | "Containerized environments for coding agents." | OSS MCP server | Docker-isolated parallel agents. |
| **Vibe Kanban** (`BloopAI/vibe-kanban`) | "Get 10X more out of Claude Code, Codex or any coding agent." | OSS desktop app | **Sunsetting** as of April 2026. |
| **CCManager** (`kbwo/ccmanager`) | "Coding Agent Session Manager for Claude Code / Gemini CLI / Codex CLI / …" | OSS CLI | Worktree-per-agent. |
| **Agent of Empires** (`njbrake/agent-of-empires`) | "Manage multiple Claude Code, OpenCode agents from TUI or Web for easy access on mobile." | OSS TUI+web | Mobile angle. tmux + worktrees. |
| **Agent Orchestrator** (`ComposioHQ/agent-orchestrator`) | "Plans tasks, spawns agents, autonomously handles CI fixes, merge conflicts, code reviews." | OSS | Goes further: actual orchestration, not just session mgmt. |
| **Ruflo** (`ruvnet/ruflo`) | "The leading agent orchestration platform for Claude. Multi-agent swarms." | OSS | Heavy framework, RAG, swarm. |
| **Anthropic Agent Teams** (`code.claude.com/docs/en/agent-teams`) | First-party experimental orchestrator built into Claude Code. | First-party | Big incumbent risk — flag explicitly. |

### Patterns across all of them

1. **Everyone leads with "parallel" + "git worktrees".** It's the
   default mental model: spawn N agents in N branches, watch them work.
2. **Almost all are agent launchers** — they spawn the `claude` process
   themselves and own the session.
3. **Most ship a TUI or desktop app.** Few have a web UI. Conductor is
   Mac-only and paid; everyone else is OSS terminal-first.
4. **None of them has a permission inbox** across workers (we checked).
5. **None of them is MCP-native** as a control surface — Container Use
   is "an MCP server for sandboxing", not "controllable via MCP from
   another agent".
6. **Most pitch is "I help YOU manage agents".** TubeMail's pitch is
   "I let an AGENT manage agents."

### What's the empty seat at the table

**Programmable, MCP-native control plane for Claude Code fleets,
operated by another Claude Code (or any MCP client).**

The crowded angle is the human-in-the-loop session manager.
The empty angle is the **bus** — transport plus operator surface, with
the actual orchestrator being whatever LLM/script/Claude session is
calling our MCP tools.

This matches our README's own framing: *"Not an orchestrator. TubeMail
ships transport plus an operator surface; it does NOT implement
orchestration policy."* That humility is the differentiator. Lean into
it instead of hiding it.

## 3. Positioning recommendation

### Current hero

> "Claude Code workers on a wire."
>
> *TubeMail lets one Claude Code session drive another. Start a worker
> in any directory, and any other Claude Code session (or MCP-aware
> agent) can send it messages, receive replies, approve permission
> prompts remotely, restart it, and watch what it's doing — all over
> HTTP/SSE + WebSocket.*

**Diagnosis:** poetic but opaque. A stranger doesn't know what
"on a wire" means until paragraph two. Compare to "Run a team of
coding agents on your Mac" (instant) or "Manage multiple AI terminal
agents like Claude Code, Codex, OpenCode, and Amp" (instant).

### Recommended hero (pick one — A is safest)

**A. Plain-English clarity**
> **Make any Claude Code session drive any other.**
> The MCP-native control bus for Claude Code fleets. One hub, a web UI,
> and an MCP tool surface so an orchestrator session — or any
> MCP-aware agent — can send work, receive replies, approve permissions,
> and watch terminals across every worker on the wire.

**B. Outsider-grok**
> **Programmable orchestration plane for Claude Code.**
> Other tools spawn parallel agents in worktrees. TubeMail gives an
> already-running Claude session the MCP tools to drive every other
> session in your fleet — including a web UI, a permission inbox, and
> recorded terminals — so orchestration isn't a TUI you operate, it's
> code an agent runs.

**C. Punchy**
> **Your Claude Code agents, on the bus.**
> Not a session manager. A transport. Drive workers from any MCP
> client, approve permissions in one inbox, watch every terminal in
> the browser.

Whichever we pick, lead the README with **a 30-second screenshot or
GIF** of the web UI (Workers tab + Permissions inbox + integrated
terminal). Every competitor leads with a screenshot. We currently have
zero. This is the single biggest README gap.

### Mandatory framing moves

1. **Name the empty seat.** First paragraph below the hero: "Other
   tools manage parallel agents for *you*. TubeMail manages them *for
   another agent*." That single sentence draws the line.
2. **Don't fight Anthropic's Agent Teams.** Acknowledge it explicitly
   in a "Why TubeMail when Agent Teams exists?" callout: Agent Teams is
   a single coordinator inside one Claude harness; TubeMail is
   out-of-process, multi-host, web-UI-bearing transport. Different
   shapes, both legitimate.
3. **Show the permission inbox screenshot.** This is the feature
   competitors don't have. Lead with it.
4. **Keep the "Not an orchestrator" line.** It's principled scope
   discipline and reads as confidence, not weakness.

## 4. Launch checklist

Bucketed by gate. Each box is a concrete action. Estimated time tags
let you defer the "after launch" items past the announcement.

### Gate 1 — must-do BEFORE flipping repo public (≈90 min)

- [ ] **Flip repo to public** (last step in this gate, after the rest
      passes review)
- [ ] **Set repo description** (≤350 chars, mirrors hero pitch). Use
      `gh repo edit disciplin-run-org/tubemail --description "…"`
- [ ] **Set repo topics:** `claude-code`, `mcp`, `mcp-server`,
      `disciplin-run`, `agent-orchestration`, `multi-agent`, `claude`,
      `anthropic`, `fastmcp`, `pty`, `developer-tools`. (`gh repo edit
      … --add-topic`)
- [ ] **Set homepage URL** to the GitHub Pages or repo URL.
- [ ] **Add SECURITY.md** — point to `jjstack/security-review.md`,
      list how to report vulns (`security@…` or private advisory).
- [ ] **Add CONTRIBUTING.md** — short. dev install, test command,
      branch convention, PR style. ≤80 lines.
- [ ] **Add CODE_OF_CONDUCT.md** — Contributor Covenant 2.1 verbatim.
- [ ] **Add CHANGELOG.md** — `0.2.0 — initial public release`. List the
      v0 → v0.2 surface.
- [ ] **Audit committed secrets** — grep for `TUBEMAIL_SECRET`, API
      keys, internal hostnames in git history. Anything in
      `jjstack/security-review.md` already cleared? If not, do it.
- [ ] **Review `jjstack/` content** — design docs are checked in. Are
      they OK to be public? (Spot-check for embarrassing internal
      reasoning, customer names, unredacted incident notes.)
- [ ] **Verify no `.env` or token files** in tree:
      `git -C tubemail ls-files | grep -E '(^|/)\.env(\.|$)|token'`
- [ ] **Fix repo description fields with `gh repo edit`** (see helper
      script in §5).

### Gate 2 — README rewrite (≈60 min)

- [ ] **Rewrite hero** to one of the three positioning options above
      (recommend A).
- [ ] **Add 1 hero screenshot** of the Workers tab with at least 2
      workers visible — save as `docs/images/hero.png`.
- [ ] **Add 1 GIF** of the permission inbox flow (≤8s, ≤2 MB) —
      `docs/images/permissions.gif`. Use `asciinema` + `agg`, or screen
      capture.
- [ ] **Add a comparison table** under "Why TubeMail" — 4 rows max:
      TubeMail vs Claude Squad vs Conductor vs Anthropic Agent Teams,
      with checkmarks for: web UI, permission inbox, MCP-driven, OSS,
      self-host. Don't be unfair — pick true differentiators only.
- [ ] **Demote the install matrix** below the screenshot. Quickstart
      should be the second thing readers see.
- [ ] **Move tool-surface table** to a separate `docs/MCP_TOOLS.md` —
      it's reference material, not landing copy.

### Gate 3 — distribution (≈45 min)

- [ ] **Publish `tubemail` to PyPI.** Build with `python -m build`,
      upload with `twine upload`. Reserve the name even if you push
      0.2.0 today.
- [ ] **Publish `tubemail-hub` to PyPI.** Same.
- [ ] **Tag `v0.2.0`** and create a GitHub Release with the CHANGELOG
      entry as the body.
- [ ] **Optional: publish Docker image** to GHCR
      (`ghcr.io/jesperjurcenoks/tubemail-hub:0.2.0` and `:latest`).
      Add a workflow under `.github/workflows/release.yml` if you want
      it automatic on tag.

### Gate 4 — launch surface (≈45 min)

- [ ] **Write Show HN draft** (≤200 words). Lead with the empty-seat
      framing: *"Most parallel-Claude-Code tools manage agents for you.
      TubeMail manages them for another agent."* Save under
      `jjstack/launch-show-hn-20260425.md`.
- [ ] **Write tweet/X thread draft** (5 posts max). Post 1 = hero.
      Post 2 = perm inbox screenshot. Post 3 = "drive from another
      Claude session" example. Post 4 = comparison row. Post 5 =
      install + GitHub link.
- [ ] **Write LinkedIn post draft** (≤1500 chars). One paragraph
      problem, one paragraph solution, one CTA.
- [ ] **r/ClaudeAI post draft** — community-focused, not promotional.
      Pose it as "I built this — would love feedback".
- [ ] **r/LocalLLaMA / r/LangChain / r/AI_Agents** — pick 1, not all.
- [ ] **Anthropic Discord** announcement under the relevant channel
      (if you're in there).
- [ ] **Open 5 "good first issue" tickets** to seed contributor
      activity. Suggested:
      - `docs: add screenshot of permissions inbox`
      - `feat: pip-installable PyPI smoke test`
      - `feat: helm chart for k8s deploy`
      - `docs: ascii cinema of orchestrator → worker flow`
      - `feat: structured event filter for `tm_get_recording``

### Gate 5 — post-launch (24 h after announce)

- [ ] **Watch GitHub issues** every 2 h for the first 12 h. First-day
      responsiveness is the strongest predictor of stars beyond the
      announcement bump.
- [ ] **Pin a "Welcome / what to try first" issue** so first-time
      visitors land on a friendly guide instead of a wall of bug
      reports.
- [ ] **Add stargazer-funnel insight** — note where stars came from
      (HN, X, Reddit) so future launches use the same channel mix.
- [ ] **Schedule a v0.2.1 patch release** for whatever first-day
      feedback surfaces. Aim for within 72 h to signal "this project
      is alive."

## 6. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Anthropic Agent Teams (first-party) cannibalises the niche before we get traction. | Position as out-of-process, multi-host, web-UI-bearing — different shape, both legitimate. State explicitly in README. |
| Reviewers ask "why not just `claude-squad`?" | Comparison table in README answers this above the fold. |
| First-day install friction — `pip install tubemail` 404s if PyPI publish slips. | Keep `pip install -e .` instructions prominent until PyPI is live. Don't ship the public README with broken install copy. |
| Security questions on day-1 about pty bridge / bearer auth. | SECURITY.md ready. Surface `jjstack/security-review.md` from it. |
| HN comment about the name "TubeMail" being weird. | It IS weird. Lean in: it's a callback to pneumatic tubes — a literal physical bus. Don't apologise. |

## 7. Decisions still open

These are NOT pre-launch blockers but the user should call them
before announce:

1. **Hero option A vs B vs C** — recommend A. Need a yes/no from user.
2. **Comparison table — include Anthropic Agent Teams or not?**
   Including it acknowledges the elephant; excluding it dodges. I lean
   include.
3. **Show HN today vs tomorrow morning ET?** Same-day risks rushing
   the README; next-morning ET (Tue 9am US Eastern) is the classic
   slot and gives time for one more pass.
4. **PyPI namespace — `tubemail` and `tubemail-hub` two packages, or
   one `tubemail[hub]` extra?** Two is what the README claims;
   collapsing is a v0.3 concern.

Mode: focused visual audit grounded in live screenshots.

Status: **Desktop UI is clean and well-organized. Tablet/mobile responsive
work is mostly missing. A handful of fixable visual issues, no design
crimes.**

Score: **7/10.**

The desktop experience is solid. The roster post-cleanup (no SSE dot, sortable
headers, ctx + rec columns) reads cleanly without feeling cramped. The
Settings page is appropriately minimal for what it has to do today. State
badges, dot indicators, and project grouping are coherent. Two-and-a-half
points off come from real responsive gaps and the absence of any visual
escalation for "this state is unusual" cases.

## D1. Roster — desktop, after the recent cleanup — 8/10

The leftmost SSE dot is gone (good — flagged by user, removed). Sortable
column headers show up/down arrow icons; active column has a stronger
arrow weight. Project grouping with `leanspecs ↳` indented children is
intact. Manager-up column shows clean green dots, state badge shows
green `idle` pills.

**What works:**
- 9-column grid resolves cleanly on desktop. Names + version + state +
  directory all visible without truncation for most rows.
- Tabular numerics on Version makes the date-stamped version strings
  align: `0.1.0+a3b8020.dirty @08:50` reads well.
- The folder icon + project-group header pattern feels intentional, not
  bolted on.
- 28 rows render without lag (informally — full list scrolls smoothly).

**What's worth fixing (no new features, just polish):**

- **Long worker names wrap or truncate inconsistently.** "Jesper Resume
  and Linkedin-tm" is the obvious one. On desktop it fits on one line; on
  tablet it wraps mid-word ("...mcp-tm"). The grid's `minmax(180px, 2fr)`
  for col 2 plus the responsive layout is doing weird things. A
  `text-overflow: ellipsis` with `title="full name"` on the cell would
  resolve the visual, and the user can hover for the full name.
- **Project header row has empty State + Mgr columns** — visually a stripe
  of empty cells. Could put "3 sessions" or similar in the state cell to
  fill it. Today the "3 sessions" label is in the cwd column, which is
  off-pattern (cwd should be a directory). Move it to State or to a
  dedicated cell.
- **The trash icon column (col 9) is empty when a worker is online**
  but the column still occupies 28px. With 28 rows and most online,
  that's 28 empty cells of right-side padding. Either remove the column
  when no row uses it, or shrink it (e.g., `minmax(0, 28px)`) when no
  visible row needs the trash.

## D2. Busy-decay state — visual differentiation gap — 5/10

The eng review and DX review both surfaced this. From the design side:

After the busy-decay fix, a worker is "busy" only when its trailing inbound
event is < 600s old. That's correct from a state-machine standpoint but
the UI has no visual signal for "this has been busy a while."

Today: amber pill + `busy 47s` counter. At 30s, 5min, 9min — same.

**Recommendation (no new feature):** introduce one threshold visual
escalation, not a gradient. At >5min busy, the badge text bolds OR the
counter color shifts to var(--warning) saturated (currently it's the
softer warning). The information is already in the DOM (the counter
text); just style it conditionally past a threshold.

This is one CSS rule and one inline className conditional. It's the
cheapest 1-point design improvement available.

## D3. Recording active vs Mgr indicator — do they fight? — 7/10

**The concern:** the Mgr column shows green when manager is up, red when
down. The Rec column shows red `CircleDot` when recording is on, hollow
gray `Circle` when off. Two greens + two reds on one row could clash.

**Tested in the wild (per the screenshots):** I have no recording-on rows
in the live state to verify, but tracing the code:

- Mgr column is a 14×14 emoji-class dot in col 3.
- Rec column is a lucide `CircleDot` size=14 in col 8.
- They're 5 columns apart; not visually adjacent.

So they don't fight in the layout. **But they DO repeat the green/red
semantic** with two slightly different glyphs (filled dot vs filled-with-
ring). A new viewer could confuse them.

**Recommendation:** when Rec is on, use the existing `--danger` red — but
also add a small "REC" pulsing keyframe or a subtle ring fade so the
recording-on state reads as *active* rather than just *colored*. The
Mgr dot is static (status indicator); the Rec dot is action (recording in
progress). They should look different beyond hue.

This is one CSS keyframe + one className. Not new functionality.

## D4. Recording-silent visual state — gap — flagged by DX review

The DX review identified this as the single highest-impact issue:
recording is on, capturing nothing, no UI surfaces this. From a design
perspective:

**The pattern already exists.** `TerminalPane.tsx` has a "Worker silent"
card (4s timeout) with a clear explanation + action button. Same shape
should apply to the Rec dot.

**Visual recommendation:**

- When recording is on AND no bytes have been written in the last 30s
  AND the worker is online: show the Rec dot in `--warning` (amber)
  instead of `--danger` (red), with a tooltip "Recording is on but no
  output captured in 30s — manager may need a roll."
- The Settings page should also surface this: add a status line under
  the recording section "Recording active for N workers, capturing for M"
  so the operator sees the discrepancy at a glance.

These reuse existing visual idioms (amber-vs-red, status footers). No
new components.

## D5. Settings page — minimalism vs growth slope — 8/10

The page today is two sections (Recording, Session) with three knobs and
one button. It looks good as is. Recording paragraph reads naturally.

**Slope concerns:**
- Three knobs is the borderline where you stop needing structure. At
  five+ the page needs section dividers, descriptions per knob, and
  probably save buttons (today everything is live-save which is fine
  for a few knobs but feels risky at scale).
- The "Sign out" button is in a different visual register from the
  Recording section. Today it works because Session has its own H3
  header. If a third or fourth section appears, the visual hierarchy
  needs to be clearer.

**No design crimes today.** Recommendations are slope guards:
- Add a top-of-page "Save changes" / "Saved" indicator. Today live-save
  silently mutates server state on every keystroke change in the number
  inputs — that's fine but invisible.
- The number inputs default-style is browser-rendered and looks dated
  next to the rest of the UI. A small CSS pass to match the rest of
  the design (border-radius, padding, focus state) is one block of CSS
  that works for any future settings page.

## D6. Popout terminal sizing — fixed today, verify — 9/10

The popout window now uses `.popout-host { height: 100vh }` + flex-fill
on `.terminal-pane`, plus `resizePopoutToFitPty` which grows the window
to match the manager's pty grid on first size message. Initial popout
opens at min(1280, 90% screen W) × min(900, 90% screen H).

**I can't visually verify the popout in this review session** (browse
opens in an embedded browser, not as a popout), but the code path is
correct. The previous bug (140px dead space at the bottom because of
`calc(100vh - 140px)` carried over from embedded mode) is structurally
resolved.

**Verification recommendation:** add a manual test note to a future
QA pass: "open a popout from the live UI, verify the prompt is at the
bottom of the visible terminal pane on first load." Not new functionality;
just a checklist item.

## D7. Responsive — tablet and mobile — 4/10

This is the biggest design gap.

**Tablet (768×1024):** sidebar still renders, CTX column gets pushed off
the right edge. DIRECTORY truncates mid-word. The 9-column grid is too
wide for this viewport. On mobile (375×812), only WORKER + MGR + VERSION
are visible; STATE + DIRECTORY + CTX + REC are all off-screen.

The jjstack rule says "All designs MUST be responsive for desktop, tablet,
and mobile." Tubemail's web UI today does NOT pass that bar.

**Honest assessment:** the persona is solo-orchestrator-on-a-laptop. The
mobile/tablet experience is currently aspirational. But the rule is the
rule.

**Cheapest fix path (no new features):**

1. Tablet (≥768px): hide the VERSION column and the trailing trash column
   when worker is online. Frees ~150px. CTX and REC become visible.
2. Mobile (<768px): collapse the roster from a grid to a stacked card
   list. Each worker becomes a card with two lines: line 1 = name + state
   badge + mgr dot; line 2 = directory + ctx% + rec toggle.
3. The sidebar collapse to top-nav already happens (visible in mobile
   screenshot), but the "Saved Messages" tab label wraps awkwardly to
   two lines. Shorten on mobile to "Flows" or "Saved" via a `[label, mobileLabel]`
   pair on SidebarTab.

This is two CSS media queries + one small component variant. No new
backend.

## D8. Permissions page — empty state missing — 6/10

The screenshot of `/?tab=permissions` rendered blank. With zero pending
permissions, the page shows nothing — no header, no "all caught up" state,
no empty-state graphic. That's a small but real design gap.

**Pattern from the codebase:** the Roster has `<div className="empty-state">
<p className="title">No workers connected</p>...</div>` for its empty
state. Same pattern, applied here, would say something like:

```
No pending permissions

Workers are running clean. When a tool prompt
needs your approval, it'll appear here.
```

One component reuse. Five lines of code.

## D9. Color palette — within limits — 9/10

Counted from `styles.css`:
- `--primary` (blue) — links, active nav, primary actions
- `--ai` (purple) — waiting_permission state, sidebar badge
- `--success` (green) — idle state, ack-received
- `--warning` (amber) — busy state
- `--danger` (red) — offline, recording-active, destructive actions
- `--gray-{50..900}` (neutral scale)

That's 5 distinct semantic colors plus a gray scale. Within the jjstack
"max 5 colors" rule. Good.

## D10. Typography — 7/10

The CSS uses:
- `--font-ui` (system stack) for chrome, badges, labels
- `--font-mono` (monospace) for version strings, terminal, code
- `JetBrains Mono` explicitly in the xterm theme

That's 3 font roles, well within limits.

**Slope concern:** `JetBrains Mono` is hardcoded in `TerminalPane.tsx:109`.
Per the jjstack rule, fonts must be free, open-source, and Google Fonts
available. JetBrains Mono IS on Google Fonts, so this is fine — but it's
not loaded via Google Fonts; it relies on the user having it installed.
A user without JetBrains Mono falls through to `'Courier New', monospace`
which is the default fallback in the same line. Acceptable.

**Recommendation (slope):** if any new font is added, load it via Google
Fonts CDN with a `<link rel="stylesheet">` in `index.html`. Don't rely
on user-installed fonts.

## D12. Logo / branding — minimal but present — 6/10

The header brand is just the text "tubemail" in the sidebar. No logo image.
No favicon (verified — `/favicon.ico` would 404 if requested; the
StaticFiles mount doesn't set one up).

Per the jjstack rules:
- 3 logo versions required (horizontal, square, simplified) — **none exist.**
- Logo must work on light AND dark backgrounds — text-based "tubemail" works on both.
- Favicon covers all platforms — **missing.**

**Honest call:** for a personal/ecosystem tool, this is acceptable. The
text wordmark is fine. The favicon gap is the only real one — even a
basic emoji-as-favicon ("📨" since this is a transport hub) would be
better than nothing because browsers tab-stack many tubemail tabs and
they're all indistinguishable today.

**Recommendation:** add a 32×32 favicon. Could be a simple "TM" monogram
or an emoji-derived PNG. One file in `frontend/public/`.

## D13. NavBar / footer — 7/10

The sidebar serves as the nav. It's consistent across pages. Active state
indicator works (blue left border on active tab).

Things that comply:
- Active state indicator ✓
- Sticky position ✓ (it's a fixed sidebar, not a top-nav, but same effect)
- Responsive collapse on mobile ✓ (collapses to horizontal nav)

Things missing or weak:
- No footer per se. The `v0.1.0` text in the lower-left of the sidebar
  is the closest thing. No copyright, no social links. For a tool running
  on localhost this is acceptable.
- The `Settings` bottom-tab pattern means Settings is visually separated
  but functionally just another tab. Consistent with leanspecs/iris-qa.

## Top 5 fixes (highest impact, lowest effort)

In priority order, no new features:

1. **Mobile/tablet roster collapse to card layout.** Two media queries +
   one component variant. Closes the responsive rule violation.
2. **Permissions empty state.** Five lines of JSX, reuses the
   `.empty-state` pattern from Roster.
3. **Busy >5min visual escalation.** One CSS rule + one className conditional.
4. **Recording-silent amber dot + tooltip.** Reuses `--warning`; adds a
   `recordingActive && noBytesIn30s` check to the Rec column.
5. **Favicon.** One PNG in `frontend/public/`. Stops every tubemail tab
   from being indistinguishable.

---

## What's NOT in scope

- Light/dark mode toggle (single-operator persona, daytime use today)
- Animation polish on tab transitions
- Custom illustrations for empty states (premature)
- Logo design (text wordmark works for the persona)
- Replacing JetBrains Mono via Google Fonts CDN (works today, slope guard only)

---

## Cross-review tension check

This review's recommendations align with both the CEO and DX reviews:

- DX review #4 ("Recording-silent state surfaces in the UI") = D4 here.
- DX review #5 ("Busy > 1 hour rendered visually distinct") = D2 here.
- CEO review's "watch the slope" on Settings = D5 here.

Three independent reviews converging on the same handful of polish items
is a strong signal that they're load-bearing, not nice-to-have. Recommend
addressing 1, 3, and 4 from "Top 5 fixes" above as part of the same
follow-up that includes the SSE eviction streaming fix from the eng
review. They're all in the same neighborhood: "the tool needs to communicate
its state more honestly."

---

## Verdict

**7/10. Ship as-is. Address the top-5 list together with the streaming
bug fix from the eng review. None of the 5 is a new feature; all are
polish on existing surfaces. After those 5 land, this scores 9/10.**
